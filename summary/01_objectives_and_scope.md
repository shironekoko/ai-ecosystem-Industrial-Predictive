# 01 · วัตถุประสงค์ ปัญหา และขอบเขต

## 1. ปัญหาที่แก้

ดอกกัด (end mill) สึกที่คมตัดตลอดการใช้งาน วัดความสึกด้วย **ความกว้างรอยสึกด้านข้าง (flank wear, VB)** ตาม ISO 8688-2 การตัดสินใจว่า **"เปลี่ยนดอกเมื่อไร"** เสียทั้งสองทาง:

| เปลี่ยนเร็วเกินไป | เปลี่ยนช้าเกินไป |
|---|---|
| ทิ้งอายุดอกที่ยังใช้ได้ · หยุดเครื่องบ่อย · ค่าดอกสูง | ผิวงาน/ขนาดเพี้ยน · ดอกแตก · เสี่ยงเสียหายต่อ spindle และชิ้นงาน |

วิธีที่โรงงานใช้กันทั่วไปมี 2 แบบ และมีจุดอ่อนทั้งคู่
- **Fixed-life** (เปลี่ยนตามอายุคงที่) — ต้องเผื่อมากถ้าอายุดอกแกว่ง ไม่รู้สภาพของดอกนั้นจริง ๆ
- **Reactive** (หยุดเครื่องไปส่องกล้องวัด VB) — เสียเวลาผลิตทุกครั้งที่วัด

สิ่งที่ฝ่ายผลิตอยากรู้ระหว่างผลิตจริง ๆ ไม่ใช่ VB แต่คือ **"ดอกนี้ใช้ได้อีกนานเท่าไร" = Remaining Useful Life (RUL)** และเมื่อถอดดอกแล้วอยากรู้ว่า **"ดอกนี้สึกจริงเท่าไร คมไหน"** เพื่อจัดการดอกที่ถอดและยืนยันว่าการตัดสินใจถูก

## 2. วัตถุประสงค์ของโปรเจกต์

| # | วัตถุประสงค์ | ระบบทำได้ด้วยอะไร |
|---|---|---|
| 1 | **บอก RUL ระหว่างผลิตโดยไม่ต้องหยุดเครื่องวัด VB** | GRU direct-RUL ใช้เฉพาะสัญญาณที่เครื่องบันทึกเอง (ไม่มี VB เป็นอินพุต) อัปเดตทุกแนวตัด (~4.4 วินาที) |
| 2 | **ตัดสินใจเปลี่ยนดอกอย่างปลอดภัย** (ไม่เปลี่ยนช้าเกิน) | คำแนะนำจาก **ค่าล่าง P10** ของ RUL (ฝั่งระวัง) · REPLACE_NOW = **interlock หยุดป้อน** รอคนตัดสิน · แจ้ง PLAN_REPLACEMENT ล่วงหน้า ~10 นาทีให้เตรียมดอก |
| 3 | **ยืนยันสภาพดอกตอนถอดด้วยเกณฑ์เดียวกัน** | วัด VB จากภาพ 4 ใบมีด (ensemble ResNet-18) → VB เฉลี่ย 4 ใบ เทียบ 103/140 µm ชุดเดียวกับ RUL → บอกการจัดการดอกที่ถอด + คมที่สึกผิดปกติ |
| 4 | **มนุษย์อยู่ในวงจรทุกจุดที่มีผลจริง** (human-in-the-loop) | ผู้ควบคุมเลือก ถอดดอก/ตัดต่อ · ผู้ตรวจยอมรับค่า AI หรือวัดจริง · admin ตัดสินแบบจำลองใหม่ · ทุกการตัดสินใจลง **Audit Trail** ในชื่อผู้ใช้ของ token |
| 5 | **เรียนรู้ต่อเนื่องอย่างปลอดภัย** | ค่าที่ผู้ตรวจวัดจริงเท่านั้นเข้า pool → retrain อัตโนมัติ → **gate** (ไม่แย่ลง) → admin promote · ย้อนเวอร์ชันได้ |
| 6 | **จัดการวงจรดอกครบจนติดตั้งดอกใหม่** | ใบเบิกดอกทดแทน (PDF) 1 ใบต่อการถอด: รอเบิก → รับจากคลัง → ติดตั้ง → เครื่องเริ่มรอบใหม่แบบหยุดชั่วคราว |
| 7 | **MLOps ที่ตรวจสอบได้** | แบบจำลองทุกเวอร์ชันอยู่ใน **MinIO** + sha256 + self-test ก่อนใช้ · TensorBoard · OpenTelemetry → Grafana |
| 8 | **งานรายวิชา** | Time series (อ.สหพงศ์): [รายงาน RUL](../timeseries_docs/tool_rul_forecast/Report_TimeSeries_Tool_RUL.md) · Non-time-series (241-353 AI Ecosystem): [รายงานวัด VB จากภาพ](../nontime_docs/tool_vb_vision/Report_NonTimeSeries_VB.md) — ทั้งสองแบบจำลองถูกใช้จริงในระบบเดียวกัน |

## 3. ผู้ใช้และบทบาท

| บทบาทในโรงงาน | ทำอะไรในระบบ | หน้าเว็บ |
|---|---|---|
| ผู้ควบคุมเครื่อง (operator) | ดู RUL/สัญญาณสด · ตอบ interlock (ถอดดอก / ตัดต่อ) · กดเริ่มตัดดอกใหม่ | Dashboard, Machine Monitoring |
| ผู้ตรวจ (inspector / QC) | ยืนยันค่า VB ที่ AI วัด หรือวัดจริงแล้วกรอก | Tool Inspection → รอตรวจสอบ |
| คลังเครื่องมือ / ช่างติดตั้ง | พิมพ์ใบเบิก (PDF) · กด "รับดอกจากคลังแล้ว" · "ติดตั้งดอกใหม่แล้ว" | Tool Inspection → ใบเบิกดอก |
| วิศวกร / admin | promote / reject แบบจำลองใหม่ · สลับ/ย้อนเวอร์ชัน · จัดการผู้ใช้ | Model Registry, Tool Inspection → โมเดล & Retrain, Users |

สิทธิ์ในระบบมี `admin`, `engineer`, `inspector` — **มีเพียง `admin` ที่ต่างออกไป** (ตรวจที่ backend ด้วย `get_current_admin_user`): reload/activate แบบจำลอง, promote/reject candidate, จัดการผู้ใช้ · ที่เหลือทุกบทบาทใช้ได้เมื่อล็อกอิน

## 4. เกณฑ์ที่ใช้ทั้งระบบ

| ค่า | ความหมาย | ที่มา |
|---|---|---|
| **VB ≥ 140 µm** | หมดอายุ (END_OF_LIFE / `eol` / REPLACE) | **เกณฑ์เฉพาะงาน** — ISO 8688-2 ไม่ได้กำหนดตัวเลขตายตัว แต่ให้ "กำหนดล่วงหน้า" (ตัวอย่างในมาตรฐาน VB = 0.3 mm) · ชุดข้อมูล LUH หยุดใช้ดอกที่ ~150 µm จึงใช้ 140 µm ที่ทุกดอกผ่านจริง (ดอกเล็กงานเก็บผิว เข้มกว่า 0.3 mm) |
| **103 µm ≤ VB < 140 µm** | เริ่มสึกเร่ง / ใกล้หมดอายุ (ACCELERATED / `accel` / MONITOR) | **มาจากข้อมูล** — SETAR พบว่าอัตราสึกต่อชั้นงานกระโดดขึ้น 1.7–3.9 เท่าเมื่อ VB เกิน ~103 µm ในทุกดอกทุกเครื่อง (SSE ต่ำสุดที่ τ = 103) = ช่วง accelerated ของเส้นโค้งการสึก 3 ช่วง |
| **VB < 103 µm** | ปกติ (STEADY / `normal` / OK) | |
| **ระดับดอก = VB เฉลี่ย 4 คม** | ใช้ตัดสินทั้งดอก | label ของ LUH คือค่าเฉลี่ยทุกคม และ ISO 8688-2 ใช้ค่าเฉลี่ยทุกฟันสำหรับรอยสึกสม่ำเสมอ · ค่ารายใบใช้บอกคมที่สึกมากสุด/เกิน 140 µm เฉพาะใบ |

ค่าเกณฑ์อยู่ในโค้ด 2 ที่ซึ่งต้องตรงกัน: `backend/app/features/tool_life/runtime.py` (`VB_ACCEL`, `VB_EOL`) และ `backend/app/features/tool_vision/vb_rules.py` — มี test `test_vb_thresholds_match_rul_model` ตรวจว่าเท่ากัน
ถ้าโรงงานใช้เกณฑ์อื่น: แบบจำลองภาพใช้ต่อได้ทันที (ทาย VB เป็นตัวเลข เปลี่ยนแค่ค่าเกณฑ์) แต่แบบจำลอง RUL ต้องสร้าง label และฝึกใหม่ (label คือ "เวลาถึงเกณฑ์")

## 5. ข้อมูล 2 ชุด และทำไมต้อง 2 ชุด

| | LUH milling (time series) | Nonastreda (ภาพ) |
|---|---|---|
| คืออะไร | สัญญาณเซนเซอร์ของการกัดจริงจนดอกหมดอายุ (run-to-failure) · 9 ดอก, 3 เครื่อง, 6,418 ไฟล์ .h5 (1 ไฟล์ = 1 แนวตัด ≈ 4.4 s) | ภาพหน้าคมมีดจาก optical bench 512 ภาพ (10 ดอก × 10–15 รอบ × 4 ใบมีด) + ค่า VB ที่วัดด้วยกล้อง (±2 µm) |
| ใช้ทำอะไร | ฝึก/ทดสอบแบบจำลอง RUL · สตรีมเป็น "เครื่องจริง" บนเว็บ | ฝึก/ทดสอบแบบจำลองวัด VB · เป็น "ภาพที่ถ่ายตอนถอดดอก" บนเว็บ |
| ทำไมใช้ชุดนี้ | ต่อเนื่องจนหมดอายุ ยาวพอทำ trend/seasonality/ADF/แบ่ง 80:20 ตามเวลา | มีภาพรายใบมีดพร้อมค่า VB ที่วัดแล้ว ไม่ต้องทำ annotation เอง |

ไม่มีชุดข้อมูลสาธารณะชุดเดียวที่มีทั้ง "สัญญาณเซนเซอร์ต่อเนื่อง" และ "ภาพใบมีด" ของดอกเดียวกัน → ระบบ **จับคู่ "เครื่องเดียวกัน ดอกเดียวกัน"**:

| เครื่อง | เซนเซอร์ (LUH) | ภาพใบมีด (Nonastreda) | สถานะ |
|---|---|---|---|
| M1 | T3 (ball screw) | ดอก 8 | ไม่เคยใช้ฝึกทั้งคู่ |
| M2 | T6 (linear drive) | ดอก 9 | ไม่เคยใช้ฝึกทั้งคู่ |
| M3 | T9 (linear drive) | ดอก 10 | ไม่เคยใช้ฝึกทั้งคู่ |

ตอนถอดดอก ระบบเลือก **รอบช่วงท้ายอายุของภาพ (VB เฉลี่ย 4 ใบ ≥ 103 µm) ที่สึกใกล้กับ VB จริงของดอก LUH ตอนถอดที่สุด** (`nonastreda.eol_run_for`) — เช่น ถอดตาม REPLACE_NOW: T3 = 116 µm → ภาพ N8 รอบ 12 (119 µm) · ถ้าผู้ควบคุมตัดต่อจนสึกมากขึ้นก็ได้ภาพที่สึกมากขึ้นตาม · ดอกใหม่ในรอบถัดไปของเครื่องได้ภาพชุดที่ยังไม่เคยตรวจ (เช่นรอบ 2: N8 รอบ 11, N9 รอบ 13, N10 รอบ 12) · ค่าจริงนี้ใช้เลือกภาพภายใน backend เท่านั้น ไม่ส่งไปหน้าเว็บหรือให้แบบจำลองเห็น

## 6. ขอบเขต: อะไรเป็นของจริง อะไรเป็นการจำลอง

| ส่วน | ในระบบนี้ | ถ้าใช้ในโรงงานจริง |
|---|---|---|
| ข้อมูลเซนเซอร์ | ไฟล์ .h5 **จริง** ของดอกที่ไม่เคยใช้ฝึก เล่นซ้ำ **ตามเวลาจริง** (500 Hz, ส่งทุก 0.1 s, deadline scheduling) · เร่ง 2–20× ได้เพื่อทดสอบ | ต่อสัญญาณจาก controller/dynamometer ตรง — โค้ดสกัดฟีเจอร์และแบบจำลองเหมือนเดิม |
| ภาพใบมีด | ภาพ **จริง** ของ Nonastreda ที่เลือกให้สึกเท่ากับดอกจริงตอนถอด | กล้องที่สถานีตรวจถ่ายภาพ 4 ใบ |
| "วัดจริง" ของผู้ตรวจ | ช่องกรอกเติม **ค่าที่ optical bench วัดไว้ในชุดข้อมูล** ให้ (แทนเครื่องวัด) ผู้ตรวจแก้ได้ | ค่าจากกล้องจุลทรรศน์/เครื่องวัดจริง |
| คลังเครื่องมือ | ใบเบิก PDF + ปุ่มเปลี่ยนสถานะ (ไม่ได้ต่อ ERP/คลังจริง) | เชื่อมระบบคลัง/ERP |
| ดอกใหม่หลังติดตั้ง | สตรีมเริ่มรอบใหม่ด้วยข้อมูลของดอกที่สงวนไว้ดอกเดิมจากรันแรก (ชุดข้อมูลมีดอกที่ไม่เคยใช้ฝึกเพียงเครื่องละ 1 ดอก) — ภาพเดิมนับเข้า retrain ครั้งเดียว | ดอกใหม่จริง |
| แบบจำลอง, API, ฐานข้อมูล, คิว, MinIO, การตัดสินใจ, audit | **ของจริงทั้งหมด** — ไม่มีค่าจำลอง/ค่าสำรองฝั่งเว็บ ถ้าแบบจำลองไม่พร้อม endpoint ที่ต้องใช้ตอบ 503 | เหมือนเดิม |

**ไม่อยู่ในขอบเขต:** ดอกแตก/บิ่นฉับพลัน (ไม่มีในข้อมูล), เงื่อนไขการตัดที่หลากหลาย (LUH ใช้เงื่อนไขเดียว), เครื่องใหม่ที่ไม่มีประวัติ (ต้องเก็บดอกที่ใช้จนหมดอายุ 1–2 ดอกก่อน — ข้ามเครื่องคลาด 11–24 นาที), การใช้ VB ที่วัดตอนถอดไปฝึกแบบจำลอง RUL อัตโนมัติ (งานต่อ)
