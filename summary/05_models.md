# 05 · แบบจำลอง — ใช้ทำอะไร ออกแบบอย่างไร ดีกว่าทางเลือกอื่นอย่างไร

ระบบมีแบบจำลองที่ใช้งานจริง **2 ตัว** ตอบคำถามคนละช่วงของอายุดอก แต่ใช้ **เกณฑ์และนิยามเดียวกัน**

| | แบบจำลอง RUL (time series) | แบบจำลองวัด VB (non-time-series) |
|---|---|---|
| ตอบคำถาม | **"อีกกี่นาทีของเวลาตัด ดอกจะถึง VB 140 µm"** (และถึง 103 µm) | **"ตอนนี้แต่ละคมสึกกี่ µm"** |
| ใช้ตอนไหน | ระหว่างตัด ทุกแนวตัดที่จบ (~4.4 s) | ตอนถอดดอก (ภาพ 4 ใบมีด) |
| อินพุต | หน้าต่าง 29 แนวตัดล่าสุด × 12 ค่า (เซนเซอร์สัมพัทธ์ + เวลาตัด + เครื่อง + ตำแหน่ง) — **ไม่มี VB** | ภาพหน้าคมมีด 1 ใบ (224×672) |
| แบบจำลอง | **GRU direct-RUL** ensemble 5 ตัว + ข้อจำกัดฟิสิกส์ (EOLTracker) | **ResNet-18 + หัว regression** ensemble 5 ตัว |
| เอาต์พุต | RUL + P10–P90 + สถานะการสึก + คำแนะนำ | VB (µm) + P10–P90 + ความน่าจะเป็น 3 โซน → ระดับดอก = เฉลี่ย 4 ใบ |
| รันที่ | backend, **numpy** (~1.6 ms/รัน) | backend, PyTorch CPU (~0.2 s/ภาพ) · retrain บน GPU |
| เก็บที่ | MinIO `models/tool-rul/<version>/` | MinIO `models/tool-vision/<version>/` |
| เวอร์ชันที่ใช้ | `tool-rul-gru-1.0.0` | `tool-vision-vb-resnet18-20261007-135808` = v2.0.0 retrain ด้วยค่าวัดจริง 24 ใบ (v2.0.0 = previous) |

ทำไมต้องมี 2 ตัว: RUL บอก **"เมื่อไร"** แต่เป็นค่าพยากรณ์จากสัญญาณทางอ้อม — ตอนถอดดอกต้องมีสิ่งที่บอก **"สึกจริงเท่าไร คมไหน"** เพื่อ (1) จัดการดอกที่ถอด (ลับคม/ตัดจำหน่าย/เก็บสำรอง) (2) จับคมที่สึกผิดปกติ (3) ให้คนยืนยันได้เร็ว และ (4) สร้างข้อมูลวัดจริงกลับไปฝึก

# A. แบบจำลอง RUL — GRU direct-RUL

รายงานเต็ม: [`Report_TimeSeries_Tool_RUL.md`](../timeseries_docs/tool_rul_forecast/Report_TimeSeries_Tool_RUL.md)

## A1. ทำไมพยากรณ์ RUL ไม่ใช่ VB
- ฝ่ายผลิตต้องการ "เหลืออีกนานเท่าไร" เพื่อวางแผน ไม่ใช่ตัวเลข VB
- VB วัดได้ต้องหยุดเครื่องไปส่องกล้อง → **ห้ามใช้ VB เป็นอินพุต** ใช้เฉพาะที่เครื่องบันทึกเอง
- ทดลองแล้ว: การพยากรณ์ VB ก่อนแล้วหาจุดตัดเกณฑ์ (StateSpace) **แย่กว่า** การเรียนเวลาถึงเกณฑ์โดยตรง (ข้อ A7)

## A2. ข้อมูลบอกอะไร → ออกแบบแบบจำลองอย่างไร
| ลักษณะที่พบในข้อมูล (การวิเคราะห์อนุกรมเวลา) | ผลต่อการออกแบบ |
|---|---|
| VB และอินพุตมี **trend ขึ้นทางเดียว ไม่นิ่ง** (Mann-Kendall τ 0.93–1.00, ADF ไม่ปฏิเสธ unit root, KPSS ปฏิเสธความนิ่ง) · VB ต้อง difference 2 ครั้งจึงนิ่ง | เรียนจาก **ระดับสะสม** (ไม่ difference ทิ้ง) · ARIMA บน VB ต้อง d = 2 = ต่อเส้นความชันล่าสุด ไม่รู้จักการเปลี่ยนระบอบ |
| **ฤดูกาลคาบ 29 แนว** ทุกดอก (= แนวที่บันทึกต่อชั้นงาน) — แรงเพิ่มตามตำแหน่ง x บนชิ้นงานแล้วรีเซ็ตเมื่อขึ้นชั้นใหม่ = "ฤดูกาลเชิงตำแหน่ง" ไม่ใช่การสึก | หน้าต่างอินพุต **29 รัน = 1 คาบเต็ม** + **ตำแหน่ง x เป็นอินพุต** ให้แบบจำลองแยกผลตำแหน่งออกจากการสึก |
| วัฏจักรเล็ก (~0.1–0.2%) ทุก 2 ชั้นของ M2 (จังหวะถอดไปวัด) | ถือเป็น noise — ฝึกด้วยสัญญาณรบกวนเสริม |
| **การเปลี่ยนระบอบที่ VB ≈ 103 µm** (SETAR: อัตราสึกกระโดด 1.7–3.9 เท่า) | แบบจำลองไม่เชิงเส้น (GRU) + ใช้ 103 µm เป็นเกณฑ์ "เริ่มสึกเร่ง" และให้ทาย 2 ค่า (ถึง 103 และถึง 140) |
| **อายุดอกต่างกันมากระหว่างเครื่อง** (M2 ≈ 83 นาที vs M1/M3 ≈ 54–56) แต่ใกล้กันมากภายในเครื่อง (CV 0.7–3%) | ต้องใส่ **หมายเลขเครื่อง (one-hot)** · baseline "อายุเฉลี่ยของเครื่อง" แข็งมาก ต้องเทียบให้ชนะ |
| outlier แบบกลุ่มทั้งชั้น (เหตุภายนอก ไม่ใช่การสึก) ยืนยันในเวลาจริงไม่ได้ | ตัวกรอง causal + noise augmentation + มัธยฐานใน EOLTracker + ตัววัด drift |
| RUL$_t$ = T$_{EOL}$ − t ไม่นิ่งโดยนิยาม แต่ **T$_{EOL}$ คงที่ต่อดอก** | ข้อจำกัดฟิสิกส์: ประมาณค่าคงที่ T$_{EOL}$ แทนการไล่ RUL ทีละรัน |
| มีแค่ 9 ดอก | แบบจำลองเล็ก, เลือกโครงสร้างแบบ nested, ประเมิน leave-one-tool-out |

## A3. อินพุต (12 ค่าต่อรัน × 29 รัน)
ทุกค่าเป็น **การเปลี่ยนแปลงจากค่าตั้งต้นของดอกเดียวกัน** (มัธยฐาน 29 รันแรกหลัง break-in — รู้ได้ในโรงงานโดยไม่ต้องวัด VB) → ตัดผลต่างของระดับ/หน่วยระหว่างเครื่อง (M1 บันทึกแรงบิดแกน Nm, M2/M3 บันทึกแรงแกน N)

| อินพุต | ที่มา |
|---|---|
| `sp_rel` แรงบิด spindle (RMS) · `ay_rel`, `ax_rel` แรง/แรงบิดมอเตอร์แกนป้อน Y (ทิศตัด), X | controller 500 Hz |
| `fx_rel`, `fres_rel` แรง Fx, แรงลัพธ์ · `fy_d`, `fz_d` (ข้ามศูนย์ได้ → ผลต่าง/แรงลัพธ์ตั้งต้น) | dynamometer 25 kHz |
| `t_hours` เวลาตัดสะสม · `m1, m2, m3` เครื่อง · `x_norm` ตำแหน่งแนวตัด | controller / แผนการผลิต |

เลือก 7 สัญญาณนี้เพราะสัมพันธ์กับ VB แบบเอกภาพทุกดอก (|Spearman ρ| ≥ 0.80) ส่วนตัวแปรความผันผวน (std, แอมพลิจูดฟันกัด) ไม่สม่ำเสมอระหว่างเครื่อง จึงไม่ใช้
ก่อนเข้าแบบจำลอง: **CausalCleaner** — Hampel filter บน residual แบบ SARIMA(0,1,0)(0,1,0)$_{29}$ (เทียบตำแหน่งเดียวกันในชั้นก่อน แล้วเทียบรันก่อน) ใช้ **อดีตเท่านั้น** ตัด spike เดี่ยว (ตีธง 0.48% ของรัน) — ผลดีกว่า STL ที่มองเห็นอนาคต (MAE 1.112 vs 1.139) และดีกว่าไม่ทำความสะอาด (1.169)

## A4. สถาปัตยกรรมและการฝึก
- **GRU 1 ชั้น hidden 32** อ่าน 29 รัน → หัวเชิงเส้น 2 ค่า [เวลาถึง 103 µm, เวลาถึง 140 µm] = 20·softplus(·) (ไม่ติดลบ) · **4,482 พารามิเตอร์/ตัว** · ensemble **5 ตัว** (เฉลี่ย)
- loss = L1(RUL) + 0.5·L1(RUL ถึง 103) · Adam lr 3×10⁻³, weight decay 10⁻⁴, 30 epoch
- **สัญญาณรบกวนเสริม N(0, 1²)** บนอินพุตเซนเซอร์ตอนฝึก — จำลองความต่างระหว่างดอก กันการจำ "ลายเซ็น" ของดอกฝึก (ไม่มี noise: MAE 2.04 · มี noise: 1.33 บน nested CV)
- ฝึกตัวใช้งานด้วย T1, T2, T4, T5, T7, T8 (เครื่องละ 2) · **T3, T6, T9 สงวนไว้** ไม่ถูกใช้ฝึก เลือกโครงสร้าง หรือปรับเทียบช่วง
- inference ใน backend เขียนสมการ GRU ด้วย numpy (`runtime.GRUEnsemble`) — ไฟล์ `.npz` มี **เวกเตอร์ทดสอบตัวเอง** ที่ต้องคำนวณได้ตรงกับ PyTorch ตอนส่งออก (คลาด < 10⁻⁶) ก่อนใช้งาน

## A5. ข้อจำกัดฟิสิกส์ — EOLTracker (หัวใจที่ทำให้ RUL นิ่งและปลอดภัย)
VB ไม่ลดลง → เวลาที่ดอกจะหมดอายุ T$_{EOL}$ เป็น **ค่าคงที่ของดอก** · ทุกรันแปลงค่าทายเป็น $\hat T_{EOL} = t + \widehat{RUL}_t$ แล้วใช้ **มัธยฐานของทุกค่าที่ผ่านมา** · RUL ที่รายงาน = max($\tilde T_{EOL}$ − t, 0)
- RUL ลดลง 1 นาทีต่อเวลาตัด 1 นาทีตามธรรมชาติ ไม่แกว่งขึ้นลงตามสัญญาณรายรัน
- มัธยฐานทนต่อค่าหลุด (ชั้นผิดปกติ 1 ชั้นขยับผลได้น้อย)
- ไม่ต้องฝึกใหม่ · ลด MAE ทั้งอายุ 1.28 → **1.11** และ 20% ท้าย 1.28 → **0.91** นาที

## A6. ช่วงความเชื่อมั่นและนโยบาย
- **P10–P90** = quantile ของความคลาด leave-one-tool-out แยกตามช่วงค่า RUL ที่ทาย (ตาราง `interval` ใน meta)
- คำแนะนำใช้ **ค่าล่าง P10** (ฝั่งระวัง): REPLACE_NOW เมื่อ P10 ≤ 1 ชั้นงาน (2.73 นาที) หรือหมดอายุ · PLAN_REPLACEMENT เมื่อ P10 ≤ 3 ชั้น (8.2 นาที) · WATCH เมื่อเข้าช่วงสึกเร่ง
- ความเข้มของนโยบายปรับได้ (เช่น P10 ≤ 0.5 ชั้น = ใช้อายุดอกมากขึ้น แลกระยะปลอดภัยน้อยลง) — เป็นการตัดสินใจเชิงธุรกิจ ไม่ใช่เรื่องของแบบจำลอง

## A7. เปรียบเทียบกับทางเลือกอื่น (leave-one-tool-out 9 ดอก, หน่วย นาทีของเวลาตัด)

**แบบจำลองที่เทียบ**
1. **Fleet reference (baseline)** — RUL = อายุเฉลี่ยของเครื่อง − เวลาตัด (สิ่งที่โรงงานทำได้โดยไม่มี AI ถ้ามีประวัติ)
2. **StateSpace (ทางอ้อม)** — VB เป็นสถานะแฝง (เพิ่มแบบ Gamma ไม่ลดลง, มีระบอบสึกเร่ง, ตัวคูณรายดอก) สังเกตจาก "VB เสมือน" (Ridge บน health indicator) ด้วย particle filter 4,000 อนุภาค → RUL = เวลาที่เส้นทาง VB ข้าม 140 µm
3. **GRU direct-RUL (ที่เลือก)**

## A8. ทำไม GRU direct-RUL ดีกว่า (สรุป)
| เทียบกับ | GRU ดีกว่าอย่างไร | ยอมรับตรง ๆ |
|---|---|---|
| **StateSpace** (พยากรณ์ VB แล้วหาจุดตัด) | แม่นกว่าทุกช่วง (1.11 vs 1.58; ช่วงท้าย 0.91 vs 1.75) · ไม่เคยทายอายุเกินจริง (0% vs 13%) · อัปเดตทุกรันไม่ใช่ทุกชั้น · ถูกกว่า (numpy vs particle filter) — เพราะ StateSpace ต้องผ่าน VB เสมือนที่เอียงต่างกันรายดอก และความคลาดของ VB ใกล้เกณฑ์ถูกขยายเป็นความคลาดของเวลา (ความชันการสึกช่วงท้ายสูง) | – |
| **Fleet reference** | แม่นกว่าทั้งอายุ (1.11 vs 1.16) · **ใช้สัญญาณของดอกนั้นเอง** ปรับค่าประมาณรายดอก · ระยะปลอดภัยต่ำสุดสูงกว่า (2.32 vs 2.00 นาที) · ใช้ได้เมื่อเงื่อนไขการตัดเปลี่ยน (baseline ทำไม่ได้) | ช่วงท้ายใกล้กัน (0.91 vs 0.90) และความต่างยังไม่มีนัยสำคัญทางสถิติ (Wilcoxon p ≥ 0.5) เพราะข้อมูล 9 ดอกเงื่อนไขการตัดคงที่ |
| **Fixed-life** | ระยะปลอดภัยต่ำสุด 2.32 vs 0.75 นาที · มีการเตือนล่วงหน้า ข้อมูลรายดอก และตรวจ drift | fixed-life ใช้อายุดอกได้มากกว่า (94.5% vs 92.1%) ในข้อมูลนี้ เพราะอายุในเครื่องเดียวกันต่างกันแค่ 0.7–3% — ในโรงงานที่อายุแกว่งมากกว่านี้ fixed-life ต้องเผื่อมากขึ้น |
| **GRU ไม่มีเซนเซอร์** | 1.11 vs 1.31 — เซนเซอร์ช่วยจริงเมื่อฝึกด้วย noise | – |
| **GRU ไม่มีฟิสิกส์** | 1.28 → 1.11 (ช่วงท้าย 1.28 → 0.91) | – |

**ทางเลือกที่ไม่ได้นำมาเทียบ และเหตุผล**
- **ARIMA / SARIMA / Holt-Winters** — ต้อง fit รายดอกจากอนุกรม VB ที่สั้น (15–31 จุดรายชั้น) ต้อง d = 2 ไม่รู้จักการเปลี่ยนระบอบ และต้องมี VB (หรือ VB เสมือนที่เอียงรายดอก) เป็นอินพุต · งานก่อนหน้าของโครงงานพบว่า ARIMA บน VB เสมือนทายอายุเกินจริงบ่อย
- **LSTM / Transformer / TCN / gradient boosting** *(เหตุผลเชิงออกแบบ — ไม่ได้ทดลองในรายงาน)*: ข้อมูลฝึกมี 6 ดอก ~3,900 หน้าต่างที่สัมพันธ์กันสูง · ลำดับสั้น 29 ขั้น → GRU 1 ชั้นเพียงพอและพารามิเตอร์น้อยกว่า LSTM (2 gate vs 3) · Transformer ต้องการข้อมูลมากกว่ามาก · สิ่งที่ทำให้แม่น/ปลอดภัยจริงคือ noise augmentation + ข้อจำกัดฟิสิกส์ ซึ่งใช้กับโครงข่ายใดก็ได้

# B. แบบจำลองวัด VB จากภาพ — ensemble 5× ResNet-18 regression

รายงานเต็ม: [`Report_NonTimeSeries_VB.md`](../nontime_docs/tool_vb_vision/Report_NonTimeSeries_VB.md)

## B1. ทำไมเปลี่ยนจากจำแนก sharp/used/dulled เป็นการวัด VB (regression)
1. **คลาสเดิมคือ VB ที่ถูกแบ่งด้วยเกณฑ์อื่น** (sharp < 71 ≤ used < 110 ≤ dulled µm) ไม่ตรงกับ 103/140 ของระบบ และ ~5% ของ label ไม่ตรงเกณฑ์ของตัวเอง · ทาย VB แปลงเป็นคลาสตามเกณฑ์ใดก็ได้ แต่ทายคลาสย้อนกลับเป็น VB ไม่ได้
2. **คลาสไม่บอกว่าใกล้เกณฑ์แค่ไหน** — 105 กับ 135 µm อยู่คลาสเดียวกัน แต่ความหมายต่างกันมาก
3. **ใช้เกณฑ์/นิยามเดียวกับ RUL ได้** — ระดับดอก = VB เฉลี่ย 4 ใบ (เหมือน label ของ LUH) · ระบบตอบคำถามเดียวกันจาก 2 แหล่ง
4. **ไม่ต้อง annotate เพิ่ม** — ทุกภาพมีค่า VB ที่วัดด้วยกล้อง Keyence (±2 µm) อยู่แล้ว
5. **ทดลองยืนยันแล้ว** (B7): ทาย VB แล้วแปลงเป็นคลาสดีกว่า classifier 3 คลาสที่ฝึกด้วยสูตรเดียวกัน และเสมอกับ classifier ที่จูนแยก (label smoothing) — แต่ระบบต้องใช้ค่า µm

## B2. การออกแบบ
- **backbone ที่ฝึกบน ImageNet + ข้อมูลของเรา → ปัญหาของเรา**: ตัดหัว 1000 คลาส ใส่หัวใหม่ `Dropout(0.3) → Linear(512 → 1)` ทาย VB/100 (ภาพ → ตัวเลข 1 ค่า เหมือน box regression ของ YOLO)
- **อินพุต 224×672 คงสัดส่วน ~3:1** — VB คือความสูงของแถบรอยสึกเหนือขอบคม การบีบเป็นจัตุรัสทำให้สเกลแนวตั้ง/แนวนอนเพี้ยน (แย่ลง 2.6 µm, 8 µm ในช่วงตัดสิน)
- **augmentation เฉพาะแบบที่ไม่เปลี่ยนสเกล µm/พิกเซล**: กลับซ้าย-ขวา, หมุน ±3°/เลื่อน ≤ 3–4%, **สี/แสงแรง** (ความสว่าง/คอนทราสต์ ±40%, อิ่มตัว ±30%, gamma 0.7–1.4, สีเพี้ยนรายช่อง ±12%), เบลอ · **ไม่ใช้** random scale/crop/zoom/flip แนวตั้ง (เปลี่ยนความสูงแถบ = เปลี่ยนคำตอบ) · คำนวณทั้ง batch บน GPU
- **การฝึก**: Huber loss (δ = 20 µm — ทนต่อดอกที่สึกถึง 347 µm), AdamW (weight decay = L2) lr 3e-4 หัว ×5, warm-up 3 epoch + cosine decay, batch 16, **60 epoch**, EMA ของน้ำหนัก, AMP บน GPU
- **ensemble 5 ตัว** ต่างกันที่ seed → เฉลี่ย (ลดความแปรปรวนระหว่าง seed ±0.4–0.8 µm) · รวม ~55.9 M พารามิเตอร์ · CPU ~0.2 s/ภาพ
- **ความไม่แน่นอน**: residual (จริง − ทาย) นอกชุดฝึกของ ensemble → ช่วง P10–P90 (รายใบ −34/+26 µm, ค่าเฉลี่ยดอก −28/+20 µm) + ความน่าจะเป็นของแต่ละโซน (กระจาย residual รอบค่าที่ทาย) → `near_threshold` / `low_confidence` บอกให้ผู้ตรวจวัดใบที่ช่วงคร่อมเกณฑ์
- **ฝึกจำนวน epoch คงที่ ไม่เก็บ best checkpoint จากดอก 7** — val ของดอก 7 ดอกเดียวต่ำสุดช่วงต้น แต่ค่าเฉลี่ย 7 fold ลดลงจนจบ (epoch 6: 29.1 → epoch 60: 20.1 µm) · เลือก epoch จาก fold อื่นได้แย่กว่า (20.7) → ใช้ epoch สุดท้าย และดอก 7 ยังเป็น gate ที่ไม่ลำเอียงของ retrain ได้ · **ทดลองจริงแล้ว (v3)**: checkpoint epoch 4–8 → test รวมดีขึ้น 24.5 → 13.6 µm แต่ underfit (ชุดฝึก 26.6 µm) และทายดอกหมดอายุ 2 ดอกว่าปกติ → คง v2

## B5. ทำไม ResNet-18 ensemble ดีกว่า
| เทียบกับ | ผล | เหตุผล |
|---|---|---|
| backbone YOLOv8n-cls | 22.4 vs 27.7 µm | YOLOv8n ถูกออกแบบให้เล็ก/เร็วสำหรับ detection · งานนี้ตรวจวันละไม่กี่ภาพ ความเร็วไม่ใช่ข้อจำกัด · YOLO ไม่มีหัว regression สำเร็จรูปให้วัด VB |
| CNN ฝึกจากศูนย์ / ResNet-18 ไม่ pretrain | 30.5 / 29.3 vs 22.4 | ข้อมูลฝึก ~300 ภาพ — **pretraining สำคัญที่สุด** |
| แช่แข็ง backbone | recall หมดอายุ 23% vs 51% | feature ของ ImageNet ยังไม่ไวต่อรอยสึก ต้อง fine-tune ทั้งตัว |
| backbone ใหญ่กว่า (ResNet-34/50, ConvNeXt, RegNetY) | 20.9–22.0 vs 19.9 | ข้อมูล 6 ดอก แบบจำลองใหญ่ไม่ได้เปรียบ |

## B6. retrain ในระบบ — ออกแบบอย่างไรและทำไม
| กติกา | เหตุผล |
|---|---|
| ใช้ **เฉพาะค่าที่ผู้ตรวจวัดจริง** | ค่าที่ "ยอมรับค่า AI" คือคำตอบของแบบจำลองเอง ฝึกด้วยมัน = confirmation bias ไม่ได้ข้อมูลใหม่ |
| เริ่มเมื่อมีค่าวัดจาก **ดอกใหม่ครบ 6 ดอก = 24 ภาพ** (นับดอก ไม่ใช่ภาพ) | ความคลาดหลักเป็นแบบคงที่รายดอก 4 ใบของดอกเดียวกันจึงเท่ากับข้อมูลใหม่ ~1 ดอก · ขั้นต่ำทางหลักการ 3 (ฝึก ≥ 2 + gate ≥ 1 ดอก) แต่ผลจริงในระบบ: 3 ดอก (12 ใบ) ไม่ผ่าน gate · 6 ดอก (24 ใบ) ผ่าน → ตั้งที่ 6 · = M1–M3 ใช้งาน 2 รอบ |
| กันดอกล่าสุด 20% **ทั้งดอก** ไว้ตรวจ gate (นับตามดอกจริงของภาพ — ทุกรอบของดอกนั้น) | ถ้าบางใบของดอกเดียวกันอยู่ในชุดฝึก แบบจำลองจะเรียน bias ของดอกนั้นไปแล้ว gate จะผ่านง่ายเกินจริง |
| fine-tune จากเวอร์ชันที่ใช้งาน (lr ÷ 3, 15 epoch/ตัว, ทุกสมาชิก) + ข้อมูลดอก 1–6 เดิม | ไม่ลืมความรู้เดิม (catastrophic forgetting) |
| **gate**: MAE ดอก 7 แย่ลง ≤ 1 µm **และ** MAE ดอกล่าสุดที่กันไว้ไม่แย่ลง | ต้องดีขึ้นกับข้อมูลใหม่โดยไม่แย่ลงกับข้อมูลเดิม |
| candidate ใช้งานเมื่อ **admin promote** เท่านั้น · ย้อนเวอร์ชันได้ | มนุษย์ตัดสินขั้นสุดท้าย · ทุกเวอร์ชันอยู่ใน MinIO |

## B7. ข้อจำกัด
ข้อมูล 10 ดอก → bias รายดอก (ดอก 8–10 ถูกทายเกินทั้งดอก +14 ถึง +29 µm) · ทายต่ำเมื่อ VB > 140 µm (−34 µm บน CV) · ช่วง P10–P90 แคบไปบนดอกใหม่ (71% vs 80%) · **MAE ~24 µm ยังไม่พอใช้แทนการวัดทุกใบ** → ออกแบบให้เป็น **เครื่องคัดกรอง**: วัดทุกใบทันที + บอกใบที่ควรวัดจริง + ค่าที่วัดกลับไปฝึก
