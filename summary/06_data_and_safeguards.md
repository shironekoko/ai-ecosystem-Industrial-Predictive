# 06 · ข้อมูล การแบ่งข้อมูล การกันข้อมูลรั่ว/สปอย และกลไกความปลอดภัย

## 1. การแบ่งข้อมูล

### LUH (time series)
| ชุด | ดอก | ใช้ทำอะไร |
|---|---|---|
| ฝึกตัวใช้งานจริง | T1, T2 (M1) · T4, T5 (M2) · T7, T8 (M3) | ฝึก GRU production + ปรับเทียบช่วง P10–P90 |
| **สงวนไว้** | **T3 (M1), T6 (M2), T9 (M3)** | สตรีมบนเว็บ = "ดอกบนเครื่อง" — ไม่ถูกใช้ฝึก เลือกโครงสร้าง หรือปรับเทียบช่วง |
| เปรียบเทียบแบบจำลอง | leave-one-tool-out 9 รอบ (ดอกทดสอบไม่มีข้อมูลตัวเองในชุดฝึก) + 80:20 **ตามเวลา** ภายในดอก (20% ท้าย = ช่วงตัดสินใจ) | ตารางผลในรายงาน |
| เลือกโครงสร้าง | nested LOTO ภายใน 6 ดอกฝึกเท่านั้น | เลือก `direct + noise` โดยไม่แตะดอกที่สงวน |

อนุกรมเวลาห้ามสุ่มแบ่ง และ label ของรันต้น ๆ ต้องรู้เวลาหมดอายุ (อนาคต) ของดอก → จึงแบ่ง **ตามดอก** ก่อน แล้วค่อยแบ่ง **ตามเวลา**

### Nonastreda (ภาพ)
| ชุด | ดอก | ภาพ | ใช้ทำอะไร |
|---|---|---|---|
| train | 1–6 | 296 | ฝึกตัวใช้งานจริง |
| val | 7 | 56 | gate ของ retrain (คงที่) |
| test | 8–10 | 160 | ทดสอบครั้งเดียวหลังเลือกเสร็จ = **ดอกบนเครื่อง M1–M3** |
| CV | 1–7 | 352 | leave-one-tool-out 7 fold เลือกแบบจำลอง |

**แบ่งตามดอก ไม่ใช่ตามภาพ** — ภาพของดอกเดียวกันหน้าตาคล้ายกันมาก แบ่งตามภาพจะได้ผลดีเกินจริง (test `test_vb_samples_split_by_tool`, `test_training_samples_never_include_machine_tools`)

## 2. กันข้อมูลรั่ว (leakage) และ train/serve skew

| ความเสี่ยง | วิธีกัน | ตรวจด้วย |
|---|---|---|
| ใช้ข้อมูลอนาคตตอนสร้างฟีเจอร์ | ทุกขั้นเป็น **causal** (ตัวกรอง outlier ใช้อดีตเท่านั้น, ค่าตั้งต้น = 29 รันแรกหลัง break-in, EOLTracker ใช้ค่าที่ผ่านมา) | รายงานหัวข้อ 2.3 |
| ฟีเจอร์ตอนฝึกกับตอนใช้งานไม่เหมือนกัน | ใช้ **ไฟล์เดียวกัน**: `rul_runtime.py` (สร้างชุดฝึก) = `backend/.../tool_life/runtime.py` (สำเนา) · `vb_model.py` ใช้ทั้งทดลอง ฝึก retrain และ inference | `test_runtime_copy_matches_source`, `test_live_features_match_training_extraction` (ฟีเจอร์จาก .h5 ระหว่างสตรีม = ตารางที่ใช้ฝึก, tolerance 10⁻⁹), `test_stream_replay_equals_offline_evaluation` |
| แบบจำลองที่โหลดไม่ใช่ตัวที่ประเมิน | **sha256** ต้องตรงกับ metadata + **self-test** (RUL: เวกเตอร์ทดสอบต้องได้ผลตรงกับตอนส่งออก; ภาพ: ผลต้องเป็นตัวเลข 1 ค่าที่จำกัด) — ไม่ผ่าน = ไม่ใช้ | `test_artifact_selftest` |
| ดอกที่สตรีมเคยถูกใช้ฝึก | streamer ไม่พยากรณ์ถ้าดอกอยู่ในรายชื่อดอกฝึกของเวอร์ชันนั้น (`blocked`) · nonastreda แยกดอก 8–10 ออกจาก training | `test_split_is_disjoint_and_machines_use_held_out_tools` |
| retrain ประเมินบนใบของดอกที่ฝึกไปแล้ว | กันดอกตรวจ gate **ทั้งดอก** | `test_retrain_holdout_splits_whole_tools` |
| retrain ด้วยคำตอบของตัวเอง | เฉพาะค่า `MANUAL` เข้า pool · ภาพเดียวกัน (ดอกเดิมถูกเล่นซ้ำ) นับครั้งเดียว | `test_auto_retrain_counts_new_tools_not_images` |

## 3. กันสปอย (ไม่เปิดเผยคำตอบระหว่างใช้งาน)

ระบบสตรีม "ข้อมูลที่มีคำตอบอยู่แล้ว" — ถ้าคำตอบหลุดไปหน้าเว็บ การสาธิต/ทดสอบจะไม่ซื่อตรง จึงมีกติกา:

| ข้อมูลที่เป็นคำตอบ | กติกา | โค้ด |
|---|---|---|
| VB ของ LUH (คอลัมน์ `wear`, `labels/wear` ใน .h5) | ตัดทิ้งตั้งแต่อ่าน `filelist.csv` · ไม่อ่านจาก .h5 ระหว่างสตรีม · อ่านได้เฉพาะ `ground_truth()` **หลังถอดดอก** (Reports) | `luh_dataset.py`, `test_schedule_has_no_labels` |
| ชื่อไฟล์ .h5 (มี VB ฝังอยู่ เช่น `…C11VB3.h5`) | ไม่ส่งออกนอก backend | `streamer.py` |
| จำนวนรันทั้งหมดของดอก | ไม่ส่ง (บอกใบ้ว่าดอกจะใช้ได้อีกกี่รัน) | `snapshot()` |
| RUL จริง | เปิดเผยหลังถอดดอกเท่านั้น (`/tool-life/evaluations`) | `_evaluate` |
| VB ของดอกจริงตอนถอด (ใช้เลือกภาพ) | คีย์ `_physical_vb_um` ถูกตัดทิ้งก่อนบันทึก/แสดง | `removal_context`, `test_removal_context_from_rul_stream_has_no_ground_truth` |
| label/VB จริงของภาพ Nonastreda | ไม่อยู่ใน payload ปกติ · ไม่เก็บในรายการตรวจ · ส่ง **ทีละใบ** เมื่อผู้ตรวจเลือก "กรอกค่าที่วัด" ของใบนั้น (เฉพาะรายการที่รอตรวจ) → ใบที่ยอมรับค่า AI ไม่ถูกเปิดเผยภายหลัง | `blade_measurement`, `test_api_payload_has_no_dataset_label` |

## 4. กลไกความปลอดภัยของการตัดสินใจ

| ชั้น | กลไก | ป้องกันอะไร |
|---|---|---|
| แบบจำลอง RUL | **noise augmentation** ตอนฝึก | จำลายเซ็นดอกฝึก → ทายเกินจริงบนดอกใหม่ |
| | **EOLTracker** (มัธยฐานของ T$_{EOL}$) | RUL แกว่ง/ค่าหลุดจากชั้นผิดปกติ |
| | **ค่าล่าง P10** ตัดสินคำแนะนำ | เปลี่ยนช้าเกิน (ผลจริง: 0/9 ดอกใน LOTO, 0/3 ดอกที่ไม่เคยเห็น) |
| | **PLAN_REPLACEMENT** ล่วงหน้า ~10 นาที | เปลี่ยนดอกแบบกะทันหัน |
| | **drift \|z\|** ของอินพุตเทียบสถิติชุดฝึก (> 4 = นอกช่วงที่เคยเห็น) + จำนวน spike ที่ถูกตัด | ใช้แบบจำลองนอกขอบเขตโดยไม่รู้ตัว |
| เครื่อง | **interlock** — REPLACE_NOW หยุดป้อน (`HOLD`) รอคน · `start` ดอกที่ถอดแล้วไม่ได้ ต้องผ่านใบเบิก | ตัดต่อโดยไม่มีใครตัดสิน · ใช้ดอกเก่าซ้ำโดยไม่ตั้งใจ |
| แบบจำลองภาพ | ช่วง P10–P90 + `near_threshold` / `low_confidence` → แนะนำวัดใบที่คร่อมเกณฑ์ · **ผู้ตรวจยืนยันทุกครั้ง** ก่อนออกใบเบิก | เชื่อ AI ในกรณีที่ไม่แน่นอน |
| MLOps | candidate ต้องผ่าน **gate** และ **admin promote** · ทุกเวอร์ชันใน MinIO **ย้อนได้** · activate ล้มเหลว = ถอยกลับอัตโนมัติ | แบบจำลองแย่ลงหลัง retrain |
| ความรับผิดชอบ | **Audit Trail** ทุกการตัดสินใจ (ถอด/override/ยืนยัน/เบิก/ติดตั้ง/retrain/promote/สลับ) ในชื่อผู้ใช้ของ token | ตรวจย้อนหลังไม่ได้ / ปลอมชื่อ |
| การเข้าถึง | JWT ทุก endpoint (ยกเว้น health/signup/login) · admin ตรวจที่ backend · token ไม่อยู่ใน URL · WebSocket ยืนยันตัวตนในข้อความแรก (4401) | เข้าถึง/สั่งงานโดยไม่ได้รับอนุญาต |

## 5. ข้อจำกัดและจุดที่ควรปรับ (ตรงไปตรงมา)

| เรื่อง | สถานะปัจจุบัน | แนวทาง |
|---|---|---|
| ข้อมูลน้อย | RUL 9 ดอก/เงื่อนไขการตัดเดียว · ภาพ 10 ดอก | ค่าที่ผู้ตรวจวัดจริงคือทางเพิ่มข้อมูลที่ออกแบบไว้แล้ว · ใช้ VB ที่วัดตอนถอดเป็น label เพิ่มของ RUL (งานต่อ) |
| เครื่องใหม่ | ข้ามเครื่องคลาด 11–24 นาที | เก็บดอกที่ใช้จนหมดอายุ 1–2 ดอกก่อนใช้ |
| ช่วงความเชื่อมั่น | RUL: T3 ครอบเพียง 46% (คลาดฝั่งปลอดภัย) · ภาพ: 71% (ตั้งใจ 80%) | ปรับเทียบใหม่จากข้อมูลใช้งานจริง |
| แบบจำลองภาพแทนการวัดไม่ได้ | MAE ~24 µm | ใช้เป็นเครื่องคัดกรอง + retrain · U-Net วัดแถบรอยสึกโดยตรง (งานต่อ) |
| **gate ของ retrain บังคับที่หน้าเว็บ** | ปุ่ม Promote ปิดเมื่อไม่ผ่าน gate แต่ backend ยังไม่ตรวจ `gate.passed` | ให้ `decide()` ตอบ 409 เมื่อไม่ผ่าน gate |
| ความลับ | `JWT_SECRET_KEY` ใน `.env.example` เป็นค่าตัวอย่าง · บัญชีตั้งต้นของเครื่องพัฒนา (admin/engineer) ถูกสร้างอัตโนมัติ · MinIO/Postgres ใช้รหัสตั้งต้น | ตั้งค่าจริงก่อนใช้นอกเครื่องพัฒนา |
| ดอกแตกฉับพลัน | ไม่มีในข้อมูล | เฝ้าระวังสัญญาณแยก (drift/alarm) |
